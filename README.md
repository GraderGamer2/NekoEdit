# NekoEdit

**A small, native, plain-text editor for Linux.**

NekoEdit is being built around one constraint: implement the necessary application machinery ourselves and avoid third-party runtime libraries. The first target is x86-64 Linux, independent of desktop environment, with native Wayland and X11 backends planned.

> **Development status: native Wayland text-editor prototype with indexed editing, TrueType font switching, responsive controls, horizontal scrolling, Find/Replace, and persistent Settings.** The editor uses a geometrically growing gap buffer, a per-line byte/visual-row index, Unicode 18.0 grapheme-aware caret movement and selection, native Wayland clipboard transfers with an optional process-exit owner, disk-backed per-document Undo/Redo journals, software-rendered TrueType glyphs, and Wayland redraw pacing that coalesces updates until both buffer release and frame completion. Settings offers runtime TTF selection, document font size (8–32px), independent UI font size (8–16px), Wrap Lines, save confirmation, and the Clipboard Service toggle; preferences persist in `~/.nekoedit/preferences`. A History tab lists document journals, opens the selected document, and provides Undo/Redo, export, and selected-history deletion; its path filter supports live case-insensitive path matching, a visible insertion caret, and horizontal scrolling for long queries. Settings and Find/Replace keep fixed, centered panel dimensions while their text follows the selected UI font. Find highlights every literal match in the document and distinguishes the current result. With wrapping disabled, a draggable bottom scrollbar supports track clicks, mouse dragging, horizontal-wheel scrolling, and Shift+vertical-wheel scrolling. Double-click selects a word and keeps whole-word selection active while dragging across words in either direction. Selection drags that reach the document or window edge continue through Wayland's implicit pointer grab and auto-scroll vertically in both wrap modes and horizontally when Wrap Lines is disabled; Ctrl+Left/Right navigates by word; Ctrl+Up/Down moves between logical lines; Shift variants extend selection; Ctrl+Home/End and Ctrl+Backspace/Delete provide document/word navigation. Ctrl+F opens Find and Ctrl+H opens Find/Replace, with Enter/F3/Shift+F3, Replace Current, and Replace All. Document typing accepts explicit XKB Unicode keysyms in `Uxxxx` through `Uxxxxxx` form and the static Unicode-annotated X.Org named-keysym set, including Latin-1, Greek, Cyrillic, Arabic, Hebrew, Thai, Hangul, Armenian, Georgian, Kana, Sinhala, Braille, and the xorgproto 2026.1 German, punctuation, and phone-keypad aliases, encoding the selected scalar as UTF-8; ASCII fallback remains available. Optional Wayland text-input-v3 preedit/commit/delete handling is implemented and mock-tested behind the explicit `NEKOEDIT_ENABLE_TEXT_INPUT=1` opt-in. Build and test #833 verified live manager binding, focus entry, document enable, and outbound state commits on GNOME Shell 46 / Mutter 46.2. The Wayland mock also covers opt-in fallback when the protocol global is absent. The nested GNOME Shell/Mutter test is being extended to verify live IBus Simple Compose preedit updates, Backspace correction, commit, and confirmed save through text-input-v3. The Wayland mock separately covers delete-surrounding and malformed-event cases. Fcitx and other external engines remain unverified, so physical XKB typing remains the default. The XKB text-v1 reader parses declared per-key/per-group key types, exact 32-bit modifier-to-level maps, up to eight levels, explicit virtual-modifier encodings, direct and recognized indirect keysym-based real modifier_map bindings, direct key-level virtualModifiers, and a bounded xkb_compat interpretation subset (recognized modifier keysyms, AnyOfOrNone/AnyOf/NoneOf/AllOf/Exactly predicates, keysym and predicate specificity, first-declaration ties, virtualModifier, and useModMapMods=level1|any), including ISO group/level symbols such as ISO_Group_Shift and ISO_Next_Group. Per-key repeat follows XKB's separate defaults: `interpret.repeat` defaults to False for compatibility interpretations, while the default interpretation enables repeat only when Group 1 / Level 1 contains a symbol. Direct key `repeat` properties override compatibility results, which are resolved only from Group 1 / Level 1. XKB type `preserve[]` masks are parsed per exact map entry; consumed modifiers are computed from the selected type and its preserved mask, and Control and Shift are filtered per key before shortcut dispatch while symbol lookup retains the full compositor state. General XKB key actions, compatibility indicators, automatic ~/.XCompose discovery, advanced preedit attributes, and text shaping remain unfinished. A static X.Org libX11 `en_US.UTF-8`-derived `Multi_key` Compose baseline with 2,140 two-symbol pairs and 564 three-symbol sequences (while preserving the editor's original 40 mappings), plus 35 standard XKB combining dead-key actions and a curated precomposition/fallback path, are implemented. Settings offers a bounded native .XCompose import action with depth-first sibling, %L, %H, and %S includes. Optional NLP1 v2 packs now provide typed Multi_key and locale-specific dead-key rules with up to seven combining marks; the loader remains compatible with v1 packs for pt_BR.UTF-8, fi_FI.UTF-8, sr_RS.UTF-8, and el_GR.UTF-8; Settings supports installed-pack selection, compiled-pack Add/Remove, and native .XCompose Import with bounded sibling, %L, %H, and %S includes. A bounded offline CLI importer now converts and installs a selected .XCompose file directly as a private NLP1 pack under ~/.nekoedit/locales/; automatic ~/.XCompose discovery remains unfinished; Settings provides native .XCompose import with bounded sibling, %L, %H, and %S include support. Output discovery and per-output integer-scale metadata (including hotplug and wl_output.done), plus wl_surface v6 preferred buffer scale/transform tracking, are implemented and mock-tested; applying scale to physical buffers, preferred/fractional scaling, release-tracked multi-buffer scheduling, and X11 remain future work. Open/Save/Save As use the in-window directory browser and same-directory atomic replacement. CI validates the mock Wayland compositor, including text-input-v3 event sequencing. A nested GNOME Shell/Mutter test is being extended to exercise live IBus Simple preedit/commit; its end-to-end Compose case is not yet passing. Fcitx, physical keyboard hardware, and provider-originated delete-surrounding still need separate desktop validation. The user has manually confirmed that whole-word text selection and drag auto-scroll behave as expected, and has separately confirmed that `Ctrl+Shift+Left` selects words correctly in the current build; physical keyboard Compose behavior and preference restoration still need separate desktop verification.

## Project principles

- **Plain text first.** No rich-text model, syntax engine, plugin host, or IDE features.
- **Native Linux interfaces.** Speak Wayland and X11 protocols directly rather than depending on GTK, Qt, Xlib, XCB, or libwayland.
- **No third-party runtime libraries.** Low-level entry, syscall, Wayland, and XKB paths use x86-64 assembly; bounded rendering, clipboard, locale, history, and preference modules use freestanding C. Both are linked into one ELF without a C runtime or third-party shared-library dependencies.
- **Software rendering.** Draw into CPU-managed pixel buffers; no OpenGL, Vulkan, EGL, or GPU requirement.
- **Use installed fonts.** Discover and parse supported system font files without Fontconfig, FreeType, or HarfBuzz.
- **Keep the interface small.** One document per window, a small menu, a status bar, and a straightforward directory browser.
- **Interoperate with the desktop.** Ordinary UTF-8 clipboard copy and paste must work with other applications.

## Current implementation

The first Wayland backend is a freestanding x86-64 assembly/C prototype. It:

1. Uses WAYLAND_SOCKET when a launcher supplies an inherited connected descriptor; otherwise reads WAYLAND_DISPLAY and XDG_RUNTIME_DIR (including absolute socket paths).
2. Connects to the Wayland Unix-domain socket using Linux system calls.
3. Discovers wl_compositor, wl_shm, xdg_wm_base, and an optional wl_seat.
4. Creates a wl_surface and an xdg_toplevel, then handles the initial configure/acknowledge sequence.
5. Allocates a memfd-backed pixel buffer, passes its descriptor to the compositor with SCM_RIGHTS, and draws a simple test surface in software.
6. Handles seat pointer and keyboard capabilities, pointer enter/leave/motion/button events, and keyboard focus, key, and modifier events.
7. Lets pointer clicks position the document caret at the nearest character insertion boundary. Holding the left button and dragging selects text across character and line boundaries. Double-click begins a whole-word selection; keeping the second press held and dragging extends or reverses the selection by complete words. Shift+Left/Right and Shift+Up/Down/Home/End extend keyboard selections; unshifted Left/Right collapse an active selection. Typing or Backspace/Delete removes the selected range. Navigation and deletion respect Unicode 18.0 extended grapheme-cluster boundaries for valid UTF-8. Focused document typing uses the bounded XKB text-v1 subset, including Unicode keysyms in Uxxxx/Uxxxxx/Uxxxxxx form and UTF-8 insertion; unsupported or incomplete maps keep the built-in US-QWERTY evdev fallback active.
8. Implements bounded byte insertion/deletion, Enter, four-space Tab, Backspace, Delete, Left/Right/Up/Down, Home, End, and Ctrl+A Select All.
9. Draws mapped glyphs from supported TrueType outlines through bounded contour flattening, 4×4 grayscale supersampling, and a 128-entry glyph bitmap cache; keeps the embedded 5×7 bitmap as a fallback. For normal redraws, requests `wl_surface.frame` and coalesces follow-up changes until both `wl_buffer.release` and `wl_callback.done` permit the next commit.
10. Responds to xdg_wm_base ping events and exits when the compositor sends xdg_toplevel.close.

The document uses an mmap-backed byte-oriented gap buffer that starts at 64 KiB and doubles geometrically on demand to a 1 GiB safety ceiling. The current document index stores per-line byte spans and visual-row counts with Fenwick prefix trees; newline changes split/merge records, while ordinary edits point-update the affected line. Open stages into its own growable mapping and commits only after a successful read and capacity reservation. Save uses a same-directory temporary file, fsync, and atomic rename; existing destination permissions/ACLs/xattrs are not preserved, and the parent directory is not fsynced after rename. Ctrl+O opens the native path prompt, Ctrl+S saves the active path (or opens Save As for Untitled), and Ctrl+Shift+S opens Save As. The supported XKB text-v1 subset translates common ASCII symbols, explicit Unicode Uxxxx/Uxxxxx/Uxxxxxx keysyms, the Unicode-annotated X.Org named keysym aliases and xorgproto 2026.1 phone/German/punctuation additions, and 35 standard combining dead-key actions, including macron, breve, caron, ogonek, above/below marks, and German T3 overlay keys. The dead-key path retains its original 52 Latin-1 precompositions, adds curated Latin Extended precompositions for macron, breve, caron, ogonek, and below-dot, and preserves unsupported pairs as base-plus-combining-mark UTF-8. The built-in US-QWERTY fallback remains available. The XKB `Multi_key` action supports 2,140 two-symbol pairs plus 564 three-symbol sequences from X.Org libX11's `en_US.UTF-8` Compose source. The original 40 editor pairs take precedence on overlap. For three-symbol input, the second scalar is buffered only when it is a recognized prefix; unknown pairs remain literal, and Backspace/Escape cancel unfinished state. Locale-based table selection and pack installation are implemented; locale packs support two-to-four-scalar Multi_key records and v2 kind-1 dead-key chains of up to seven combining marks followed by a base scalar; legacy v1 packs remain readable. Automatic system/user .XCompose discovery and merging at startup, dead-key chains longer than seven marks, and locale rules with non-Unicode inputs remain unfinished. The reader supports up to 64 declared key types, 32 map entries per type, four symbol groups, eight levels per group, and up to 24 named virtual modifiers. It keeps each declaration index separate from that modifier's effective 32-bit encoding, and parses explicit `virtual_modifiers NAME = ...` assignments using real modifier combinations (for example `Mod4+Mod5`), numeric masks, or `none`. The custom fixture verifies `LevelThree = Mod5`, `NumLock = Mod2`, a combined real-modifier mask, a high-bit mask at bit 31, and repeated declarations in a later section. The lookup filters the compositor's full modifier state through each type's declared `modifiers` mask and uses exact `map[combination] = LevelN` lookup; numeric masks and numeric or `LevelN` level values are accepted. Unsupported or malformed type definitions fail closed to the built-in US-QWERTY fallback. The reader resolves direct keycode and recognized indirect keysym `modifier_map` entries; direct key-level `virtualModifiers` and bounded `xkb_compat` interpretation results contribute to effective 32-bit virtual-modifier masks. Compatibility interpretations support recognized modifier keysyms, all five real-modifier predicates, implicit `Exactly(mask)`, specificity/tie ordering, `virtualModifier`, `useModMapMods=level1|any`, and per-key repeat policy. General stateful XKB key actions and compatibility indicators remain compositor-owned or unfinished. Per-entry `preserve[]` and consumed-modifier filtering are implemented for Control and Shift shortcut handling; Alt and other modifiers are not yet part of the shortcut filter. Extended Compose tables and full locale behavior also remain unsupported. LevelThree and NumLock retain conventional Mod5/Mod2 fallback masks when a keymap omits explicit encodings. Optional Wayland text-input-v3 is implemented; advanced preedit attributes and live compositor validation remain follow-ups. Ctrl+C/X/V use the Wayland data-device manager and `text/plain;charset=utf-8`/`text/plain`; paste is asynchronous and limited to 64 MiB. Ctrl+Z/Y (also Ctrl+Shift+Z) uses per-document disk-backed delta journals under ~/.nekoedit. New version-2 records use compact variable-length offsets and lengths; existing version-1 journals remain readable and writable. The History tab searches stored document paths, has an Open Selected action and a Browse picker, and deletes the highlighted journal rather than an unrelated active document. The renderer uses proportional TrueType metrics and grapheme-aware movement. Direct Unicode keysym input is supported, but complex shaping, bidirectional layout, kerning, ligatures, and combining-mark positioning are not implemented. Double-click selects a word; Ctrl+Left/Right moves between words; Ctrl+Up/Down moves between logical lines; Shift extends these selections. Ctrl+Home/End moves to document boundaries, and Ctrl+Backspace/Delete removes a word. Ctrl+F/H opens literal Find/Replace with Enter/F3/Shift+F3 navigation, Ctrl+Enter replacement, and Replace All. Search-field keyboard entry is limited to the supported ASCII XKB subset. Settings persist document font size (8–32px), UI font size (8–16px), Wrap Lines, Confirm before saving, and the last successfully loaded TTF path. Settings and Find/Replace use fixed-size centered panel geometry; their glyph sizes and pointer hit maps follow the selected UI font without enlarging the panels. Find paints all literal query matches in amber while the current selected result remains distinct. The no-wrap horizontal viewport includes a draggable bottom thumb, native horizontal-wheel and Shift+vertical-wheel scrolling, caret-following, viewport-aware selection painting, and offset-aware pointer hit-testing. Output/fractional scaling, release-tracked multi-buffer scheduling, and X11 remain future work.

See [docs/WAYLAND_BACKEND.md](docs/WAYLAND_BACKEND.md) for protocol details and [docs/COMPOSE.md](docs/COMPOSE.md) for the Compose table's source and supported subset.

## Target and compatibility

| Area | Initial target |
| --- | --- |
| CPU / ABI | x86-64, System V ABI |
| Operating system | Linux |
| Display | Wayland first; X11 planned |
| Desktop environments | DE-independent; no GNOME/KDE-specific integration |
| Implementation | GNU assembler (as), Intel syntax |
| Linker | GNU ld |
| Runtime libraries | None |
| Rendering | CPU software renderer |
| Document format | UTF-8 plain text |

This is a Linux application, not a cross-platform application in the first release. The Wayland and X11 backends are intended to work across compatible compositors and window managers, not to depend on a particular desktop environment.

## Runtime dependency policy

NekoEdit will not dynamically link to third-party libraries. In particular, the runtime must not require GTK, Qt, libc, libwayland, Xlib, XCB, Fontconfig, FreeType, HarfBuzz, D-Bus, a toolkit file chooser, or a GPU API.

The unavoidable environment is the Linux kernel and a running Wayland compositor or X11 server. System font files will be used for text rendering. Build tools are not runtime dependencies.

The current build uses GNU binutils (`as`, `ld`, and `readelf`), GNU Make, and a C compiler (`cc`, GCC or Clang) for the freestanding rasterizer. The C module is compiled without libc/builtins; the final executable remains a static freestanding ELF. NASM is not required.

## Build

On an x86-64 Linux development machine with GNU binutils, GNU Make, and a C compiler installed:

~~~sh
make
make test
make test-wayland
~~~

The output is **build/nekoedit**. For a per-user installation with a command-line entry and desktop launcher:

~~~sh
make install-user
~~~

The launcher appears in the desktop application menu as **NekoEdit**, and the executable is installed at `~/.local/bin/nekoedit`. Open a terminal and run `nekoedit [FILE]` (or use `~/.local/bin/nekoedit [FILE]` when that directory is not in PATH). The installed `.desktop` entry advertises `text/plain` files under **Open With**. To also make NekoEdit the default plain-text handler, use `make install-user MAKE_DEFAULT=1`; this changes the user's `text/plain` association. To remove the per-user installation, run `make uninstall-user`. A system-wide installation is available through `sudo make install` (or a package build using DESTDIR).

Run inside a Wayland desktop session:

~~~sh
./build/nekoedit
# or explicitly:
./build/nekoedit --backend=wayland
~~~

The window starts at 800×480 and shows clickable Minimize, Maximize/Restore, and Close controls, a **File** menu, active document tab, editor area, and status bar with logical line, column, byte count, and ASCII mode. The compositor may resize it; dragging its edges/corners starts an xdg-shell interactive resize, while dragging blank title-bar space starts an xdg-shell move. Maximize/Restore waits for the compositor's configure/acknowledge sequence before replacing and committing the resized software buffer. Select **File → Open** or press **Ctrl+O** to browse directories in the native in-window picker; its Search field displays up to five selectable filename suggestions. **File → Save As** or **Ctrl+Shift+S** chooses a destination in the same picker. **File → Save** or **Ctrl+S** saves the active path, while Ctrl+S on Untitled opens Save As. Press Enter to confirm or Escape to cancel. Relative paths are resolved from the working directory NekoEdit was launched in, and absolute paths are supported. Launch `nekoedit FILE` to load a file immediately. Click within the document area to place the caret or drag with the left mouse button to select text. Hold Shift while using the arrow keys or Home/End to extend a keyboard selection. Typing or Backspace/Delete removes the selected range. Navigation and deletion respect Unicode 18.0 extended grapheme-cluster boundaries for valid UTF-8. Focus the window and type basic US-QWERTY ASCII text. The arrow keys, Home/End, Backspace/Delete, Enter, and Tab are supported. Long lines wrap by default. Open Settings → Wrap Lines to disable soft wrapping; horizontal-wheel or Shift+vertical-wheel input then scrolls the long line, and the viewport follows the caret. Re-enable Wrap Lines to return to the normal wrapped layout. Use the compositor's normal close button to exit.

### TrueType font rendering

NekoEdit currently has a dependency-free TrueType `.ttf` outline renderer. It tries DejaVu Sans Mono, Liberation Mono, and DejaVu Sans at common Debian font paths. To choose a specific file, set `NEKOEDIT_FONT`:

~~~sh
NEKOEDIT_FONT=/absolute/path/to/font.ttf ./build/nekoedit [file]
~~~

The parser supports TrueType `glyf` simple and composite outlines, cmap formats 4/12, and quadratic contours. Glyphs are rasterized into bounded 64×64 grayscale bitmaps using 4×4 coverage sampling and a 128-entry cache, then blended by the Wayland software renderer. Document wrapping, the visual-row index, pointer hit-testing, selection, and painting use hmtx-derived pixel advances at the active document em size; vertical row pitch uses scaled OS/2 typographic metrics when USE_TYPO_METRICS is set, with hhea metrics as fallback. `NEKOEDIT_FONT` overrides deterministic attempts at DejaVu Sans Mono, Liberation Mono, and DejaVu Sans. The em size defaults to 12px and is adjustable from Settings (8–32px in two-pixel steps); the UI font is independently adjustable from 8–16px in one-pixel steps. The selected font path and both font sizes persist between launches. Hinting, CFF/CFF2, variable/color fonts, kerning, shaping, ligatures, combining-mark placement, and complex-script layout are not implemented. Only the first Unicode scalar of each grapheme is rasterized; unsupported glyphs retain the embedded 5×7 fallback.

### Persistent Settings

NekoEdit loads and saves the document font size, UI font size, Wrap Lines state, Confirm before saving, Clipboard Service state, and last successfully loaded TrueType file. The configuration is stored at `$HOME/.nekoedit/preferences` (normally `~/.nekoedit/preferences`). `XDG_CONFIG_HOME` is intentionally ignored. The directory is created with mode 0700 and the preferences file uses mode 0600. Updates are written to a temporary file, fsynced, and atomically renamed into place.

The environment variable `NEKOEDIT_FONT` still takes priority over the saved font path. When it is absent or invalid, NekoEdit tries the saved path before the deterministic system-font candidates. Set `NEKOEDIT_DISABLE_PREFERENCES=1` to ignore persistent settings (useful for deterministic tests).

The X11 backend is not ready. The explicit selector currently reports this rather than silently trying to use Wayland:

~~~sh
./build/nekoedit --backend=x11
~~~

The CLI also supports --help and --version.

## Compose locale packs

The core executable embeds default en_US Compose tables. Four external datasets are provided: `pt_BR.UTF-8`, `fi_FI.UTF-8`, `sr_RS.UTF-8`, and `el_GR.UTF-8`. Each is a complete flattened table over the pinned X.Org libX11 en_US baseline, with the locale's supported `Multi_key` and up-to-three-mark dead-key rules followed by a base scalar. The standalone Greek source is merged explicitly with `--locale-standalone`; the other three sources carry their en_US include. `tools/import_xcompose.py` regenerates their JSON inputs; `make locale-packs` builds separate `.nlp` files, and the Release workflow attaches all packs with their source notices when a GitHub Release is published. In Settings, **Locale** opens an in-menu dropdown populated dynamically from `~/.nekoedit/locales/`, with built-in en_US plus every installed `.nlp` pack. The list refreshes when Settings opens and after Add/Remove, so selecting an installed locale never opens the file picker. Use the mouse or Up/Down/Enter; Escape closes the dropdown. **Add** imports a compiled local .nlp pack, **Import** converts a selected UTF-8 .XCompose file directly into a separate .nlp pack, expanding bounded quoted sibling and %L/%H/%S includes in depth-first order, and **Remove** deletes the selected optional pack after confirmation. The Add picker labels the selected directory as **SOURCE** and shows the installation target as `~/.nekoedit/locales/`; imported packs are copied there and the source file remains untouched. Choices persist in `~/.nekoedit/preferences`. Without a saved choice, NekoEdit checks `NEKOEDIT_LOCALE`, then `LC_ALL`, `LC_CTYPE`, and `LANG`. Locale names normalize language/territory casing and common UTF-8 codeset spellings (for example `fi_FI.utf8` and `sr_RS.UTF8`) to canonical pack filenames. A missing or invalid selected pack leaves en_US active and displays `MISSING`. Packs remain data-only; no network access or runtime shared libraries are required. See [docs/COMPOSE_PACK_FORMAT.md](docs/COMPOSE_PACK_FORMAT.md).

**Modular distribution boundary:** the editor executable contains only its built-in en_US baseline. The pt_BR, fi_FI, sr_RS, el_GR, and user-imported locale tables remain separate .nlp files and are never linked into the executable. The Settings Import action uses the bounded native parser to create one private user pack under ~/.nekoedit/locales/; selected-file imports can expand sibling, %L, %H, and %S includes without automatic startup discovery. The make locale-packs target builds optional release datasets under build/locales/, and the Release workflow publishes them as separate assets for users who choose to download them. The ordinary editor build remains independent of those pack files.

## Document context menu

Right-clicking inside the document viewport opens a small in-surface menu with exactly three commands: **Copy**, **Paste**, and **Cut**. Opening it preserves the current selection. The commands reuse the existing native Wayland clipboard/data-device implementation; Escape and an outside click dismiss the popup.

## Clipboard ownership

Copying must create an independent immutable snapshot of the selected bytes. The snapshot must not point into the document's gap buffer. It remains valid when the copied range is deleted, edited, or its document is closed. Clipboard transfers already in progress keep their own reference to that snapshot until the transfer completes.

The active Wayland implementation retains an independent immutable snapshot while NekoEdit owns the selection and keeps snapshots alive for in-flight sends. It has eight reusable source records, four concurrent outgoing-send slots, and a 64 MiB payload/receive limit; these are resource/concurrency limits rather than a lifetime count of sequential copy/paste commands. When Clipboard Service is enabled, a forked `nekoedit-clip` helper inherits the current Wayland connection and serves the selection after the editor window closes. The helper detaches from the launching terminal, releases the editor's history state, destroys the inherited xdg toplevel/surface/buffer, and retains only the clipboard service loop and its in-flight sends. It exits when another application replaces the selection or the compositor disconnects. This persists only the latest clipboard contents until logout/session teardown; it is not a clipboard-history database. Paste targets the editor document, not picker fields.

See [docs/CLIPBOARD.md](docs/CLIPBOARD.md).

Undo/Redo uses a per-document disk-backed delta journal under `~/.nekoedit/*.history`, with restart recovery guarded by the checksum of the last saved document. The History tab exposes Undo/Redo counts, Export, and Delete for the active document. See [docs/UNDO.md](docs/UNDO.md) for the journal format, recovery rules, and storage limits.

## File picker

The implemented file picker is a small in-window directory browser rather than a platform dialog or a complex file manager. It shows the current path, folders and files, Up and Home controls, a Show hidden checkbox, editable filename search with selectable autocomplete suggestions, and Open/Save controls. It does not require a portal, D-Bus, GTK, or Qt.

See [docs/FILE_PICKER.md](docs/FILE_PICKER.md).

## Rendering and fonts

The active Wayland renderer uses CPU-side shared-memory pixel buffers and a 128-entry TrueType glyph cache. It parses bounded SFNT/cmap/hhea/hmtx/glyf data, rasterizes quadratic outlines with 4×4 grayscale coverage, and blends glyph masks into the surface. Proportional hmtx advances and hhea-derived vertical line pitch are integrated into document layout, selection, pointer mapping, and rendering. Font loading uses `NEKOEDIT_FONT` or deterministic common Debian paths rather than recursive discovery. This scoped renderer is not a replacement for FreeType or HarfBuzz; hinting, CFF/CFF2, variable/color fonts, kerning, complex shaping, bidi, and mark positioning remain unsupported.

See [docs/RENDERING.md](docs/RENDERING.md).

## Development roadmap

1. Freestanding ELF bootstrap and syscall conventions. (Implemented.)
2. Native Wayland window, xdg-shell setup, and software-buffer proof of concept. (Implemented prototype.)
3. Pointer/keyboard editing, in-window file operations, and initial ASCII document editing. (Implemented prototype.)
4. XKB and keyboard-layout interoperability. Implemented: bounded XKB text-v1 parsing; per-key/per-group types, four groups and eight levels; exact 32-bit modifier maps; up to 24 virtual modifiers; direct and recognized indirect `modifier_map` bindings; bounded `xkb_compat` predicates including the implicit `Exactly(mask)` form, specificity/tie handling, `useModMapMods=level1|any`, and compatibility repeat defaults; per-entry `preserve[]` and per-key consumed Control/Shift shortcut handling. Character translation includes direct `Uxxxx`–`Uxxxxxx` notation and the Unicode-annotated X.Org named keysym set, plus xorgproto 2026.1's SSHARP, single-angle quotation marks, phone-numeric aliases, and `dead_apostrophe`; CI covers Arabic, Hebrew, Thai, Hangul, Armenian, Georgian, Kana, Sinhala, Braille, and UTF-8 insertion. 35 XKB combining dead-key actions with a curated Latin-1/Latin Extended precomposition table, the built-in en_US two-/three-symbol `Multi_key` baseline, and a runtime NLP1 loader for optional typed v2 records (two-to-four `Multi_key` inputs and two-to-eight dead-key inputs) with multi-scalar results are implemented. pt_BR.UTF-8, fi_FI.UTF-8, and sr_RS.UTF-8 include locale-specific dead-key sequences; Settings supports generic selection, local installation, and confirmed removal of installed packs. Optional Wayland text-input-v3 preedit/commit/delete integration is implemented and mock-tested; the capability-aware GNOME/Mutter smoke test now verifies the manager/focus/enable/state-commit handshake when supported and physical-XKB fallback when not advertised. A real input-method-provider exchange, physical keyboard coverage, and other desktop environments remain unverified. Remaining: additional locale datasets, automatic system/user Compose discovery at startup, chains longer than seven dead-key actions, general stateful XKB actions and indicators (compositor-owned on Wayland), and broader shortcut policy if more modifiers are bound. Unsupported or malformed keymaps continue to fail closed to the built-in US-QWERTY fallback.
5. Document storage, navigation, Unicode editing, history, and scrolling. Geometric gap-buffer growth, indexed per-line byte/visual-row records and Fenwick trees, Unicode 18.0 grapheme navigation/deletion, vertical/horizontal scrolling, grouped delta-based Ctrl+Z/Y history under `~/.nekoedit/*.history`, and UTF-8 insertion from explicit and curated named XKB Unicode keysyms are implemented. The History tab exposes journal counts, Export, and Delete; restart recovery is guarded by the last-saved document checksum. The six-accent dead-key path and the 2,140-pair/two-symbol plus 564-sequence/three-symbol `Multi_key` Compose paths are also covered by the mock suite. Whole-word mouse drag selection and edge auto-scroll are implemented. The en_US Compose baseline is embedded as the built-in default; optional non-en_US locale packs are separate data-only downloads handled by the bounded runtime loader and generic Settings pack manager. NLP1 v2 supports eight-input dead-key sequences and multi-scalar outputs, while v1 records remain readable. Automatic system/user Compose-file discovery and merging at startup, locale dead-key chains longer than seven actions, and live GNOME/Mutter IME verification remain unfinished; selected-file import supports sibling, %H, %S, and %L (including compose.dir resolution). Complex shaping is a separate typography milestone.
6. TrueType parsing, glyph rasterization, proportional advance layout, font-metric line pitch, runtime font selection, and independent document/UI font-size controls are implemented. Persistent document/UI sizes, Wrap Lines, save confirmation, and the selected font path are implemented in `~/.nekoedit/preferences`; advanced shaping remains unfinished.
7. File open/save, the directory-browser picker, Wayland clipboard interoperability (Ctrl+C/X/V), and an optional process-exit clipboard owner (`nekoedit-clip`) are implemented. The helper hands off the same Wayland client connection, needs no extra executable or runtime library, and is toggleable in Settings. X11 clipboard support remains part of the future X11 backend.
8. Output-scale/fractional-scale handling, multi-buffer frame scheduling, X11 backend, compatibility testing, and profiling. Compositor-configured window resizing is implemented.

Correctness and interoperability take priority over arbitrary binary-size targets.
