**Runtime font switching:** Settings now opens a dedicated TTF picker. SFNT replacement is transactional: an invalid candidate restores the complete previous table/metric state and leaves its mmap active; a valid replacement unmaps the old face, clears all face-local glyph masks, and rebuilds line geometry and the indexed visual-row layout. The test fixture confirms malformed-font rollback and successful replacement with a different outline/advance for the same glyph ID.  
**Settings typography and view:** the Settings dropdown stays open while adjusting document font size (8–32px, 2px steps) or UI font size (8–16px, 1px steps). Both settings are session-only; defaults are 12px and 10px respectively. The session-only Wrap Lines toggle defaults to ON. When OFF, each logical line contributes one visual row and the editor supports horizontal wheel/Shift+vertical-wheel scrolling, caret-following, offset-aware pointer hit-testing, and viewport-clipped selection painting. No dedicated draggable horizontal scrollbar is present yet.  
**Picker and status typography:** Open/Save picker text and the path prompt follow the UI font preference, scaling down only when the available window geometry requires it. The centered picker uses a maximum 744×424 design box and maintains 16px minimum window margins; it displays 13 rows at 16px each. The Open/Save title strip and Location label occupy separate baselines. Footer line/column/byte values use the active UI font and equal-width digit cells measured from the widest numeral, preventing proportional-font jitter.  
**Clipboard:** Wayland Ctrl+C/X/V use immutable snapshots and asynchronous nonblocking data-device transfers with UTF-8 plain-text MIME types and a 64 MiB transfer ceiling. The integration test verifies external copy/cut and paste.  
**Undo/redo:** Ctrl+Z, Ctrl+Y and Ctrl+Shift+Z use bounded snapshots that restore bytes, caret and selection; 16 entries per stack, 32 MiB aggregate history budget, and 4 MiB maximum per snapshot. Opening a new document resets history; editing after Undo clears Redo.

## Phase 6 font-engine progress

The dependency-free TrueType pipeline is implemented across `src/font/sfnt.S` and `src/font/rasterizer.c`. It first honors an explicit `NEKOEDIT_FONT` path, then tries DejaVu Sans Mono, Liberation Mono, and DejaVu Sans in common Debian font locations. The file is mapped read-only; the SFNT directory and required `head`, `hhea`, `maxp`, `hmtx`, `loca`, `glyf`, and `cmap` tables are validated. Unicode cmap formats 4 and 12 map code points to glyph IDs, and horizontal advances are read. Short and long `loca` entries are resolved with glyph-span bounds checks.

Simple and composite glyphs are decoded into fixed scratch arrays with a 256-contour and 4,096-point ceiling. The simple decoder validates contour endpoints, instruction lengths, repeated flag runs, and signed/short X and Y deltas. The composite decoder merges multiple child outlines with a 16-level recursion limit and cycle detection; validates component spans and point references; supports signed byte/word XY offsets, unsigned byte/word point matching, uniform scaling, independent X/Y scaling, and the full 2×2 F2Dot14 matrix; and checks the final contour/point limits before merging. Composite instruction payloads are bounded and skipped because hinting is not implemented. `ROUND_XY_TO_GRID` and `USE_MY_METRICS` behavior are not applied yet; composite advances currently use the composite glyph's own `hmtx` entry. Empty glyphs succeed; malformed/out-of-range glyphs and unsupported/reserved flag encodings fail cleanly.

**Current font-rendering and layout state:** The dependency-free TrueType pipeline parses bounded SFNT tables, cmap formats 4/12, simple/composite glyf outlines, hmtx advances, and OS/2 sTypoAscender/sTypoDescender/sTypoLineGap when USE_TYPO_METRICS is set (otherwise hhea ascent/descent/lineGap). Quadratic outlines are rasterized to 32×32 maximum grayscale masks with 4×4 coverage sampling and a 128-entry glyph cache. Document layout now uses proportional hmtx advances (12px em, nearest-pixel rounding, 1–32px advance bounds) for wrapping, visual-row indexing, pointer hit-testing, selection geometry, and rendering. Vertical line pitch is derived from the scaled OS/2 typographic line box when USE_TYPO_METRICS is set, with hhea fallback, rounded up and clamped to 12–32px; the no-font fallback retains the 12px pitch and embedded 5×7 bitmap. `NEKOEDIT_FONT` overrides deterministic DejaVu Sans Mono, Liberation Mono, and DejaVu Sans path attempts. Font/font-size Settings controls, runtime em-size changes, kerning, shaping, and combining-mark placement remain unfinished.

## Settings dropdown and save confirmation

The title bar now has **File** and **Settings** dropdowns. Settings currently contains **Confirm before saving**, enabled by default. File > Save and Ctrl+S open a centered Save/Cancel dialog. Saving a new Save As target also opens the dialog; choosing Cancel leaves the target and document untouched. Save As for an existing regular file retains its separate overwrite confirmation.

The toggle currently changes behavior for the running session only and resets to the default-enabled state on the next launch. Persisting user preferences is still required.

Font controls remain planned for the Settings dropdown: **Font…** will choose a supported TrueType file, and **Font size…** will change the em size. The underlying proportional layout and vertical hhea-derived line box are now integrated with wrapping, the visual-row index, hit-testing, selection, caret placement, and scrollbar geometry. The controls are still withheld because runtime font switching/size changes, cache invalidation, line-index reflow, and persistent preference storage have not been implemented.

## Latest editor-scrollbar implementation

The editor now draws a proportional vertical scrollbar only when visual content exceeds the viewport. Wayland wheel deltas scroll the document independently of the picker; the thumb can be dragged or repositioned by clicking elsewhere on its track. The text layout reserves a 24-pixel gutter, and the mock suite verifies thumb rendering and navigation against a 65,537-byte wrapped document. Actions #316 passes all eight workflow steps. Manual scrollbar interaction on GNOME/Mutter remains the next desktop check.

**Next roadmap priorities:** expose Font… and Font size… once runtime font switching, glyph-cache invalidation, metric recomputation, and index reflow can be changed safely; then implement kerning/OpenType shaping, grapheme-aware mark positioning, broader font discovery/fallback, and persistent preferences. Proportional hmtx advances and OS/2 typographic metrics with hhea fallback are now part of the active document layout. The 12px em remains fixed at runtime; Unicode keyboard input, shaping/IME, and horizontal scrolling remain separate work.

## Runtime and build interface

The application is a freestanding Linux x86-64 GNU assembly program, linked without a C runtime or third-party shared-library dependencies.

Build and test from the repository root:

```sh
make clean all
make test
make test-wayland
make inspect
```

The Makefile output is `build/nekoedit`. Run the Wayland build with:

```sh
./build/nekoedit --backend=wayland
```

The standalone binary can be run using the established form:

```sh
./nekoedit --backend=wayland
```

A file can be loaded positionally:

```sh
./build/nekoedit /path/to/document.txt
```

Do not change the existing `--backend=wayland` launch behavior as a shortcut for implementing missing editor features. The editor functionality belongs inside the application.

## Important UTF-8 boundary

The document core now implements **extended grapheme-cluster-aware editing**, but this is not full Unicode input/rendering support:

- UTF-8 is decoded as valid 1-, 2-, 3-, and 4-byte scalar values, then segmented into Unicode 18.0 extended grapheme clusters for navigation, hit-testing, selection, Backspace, and Delete. The embedded tables cover UAX #29 rules including combining/spacing marks, Hangul, Prepend, Indic conjuncts, emoji ZWJ sequences, modifiers and regional-indicator pairing.
- Malformed bytes remain individually addressable/editable.
- Non-ASCII code points and malformed bytes currently render as a single `?` placeholder cell.
- Physical keyboard/XKB text insertion remains ASCII-only.
- No Wayland text-input/IME, compose/dead-key system, or non-ASCII keysyms.
- Non-ASCII text entry remains ASCII-only; no Wayland text-input/IME, compose/dead-key system, or non-ASCII keysyms.
- The byte-oriented gap buffer and separate Open staging mapping now grow geometrically from 64 KiB up to a 1 GiB safety ceiling. Actions #312 verifies exact-capacity insertion and 65,537-byte picker Open/save. Files above that explicit ceiling remain unsupported.
